# Концепция и изисквания

## Обща концепция

**BikeStore** е уеб приложение за малък/среден магазин за велосипеди, което позволява разглеждане на каталога, покупка и резервация за наем. Служители обработват поръчки и резервации, администраторът управлява велосипеди, категории, цени, наличности и потребители.

## Основна цел

Една система за две търговски дейности с проследима наличност, ясна информация за велосипеда и надеждно обработване на заявки от клиент до служител.

## Целеви групи

- **Гост:** разглежда каталог, категории и детайли.
- **Клиент:** регистрира се, влиза, избира покупка или период на наем, вижда статусите на собствените си заявки.
- **Служител:** приема/обработва поръчки, потвърждава и приключва наеми, актуализира наличности според предоставените права.
- **Администратор:** управлява продуктовия каталог, роли, цени, потребители и справки.

## Основни потребителски сценарии

1. Гост отваря каталог → филтрира → вижда детайли → избира регистрация.
2. Клиент избира велосипед → определя количество → потвърждава поръчка → вижда статус.
3. Клиент избира велосипед за наем → избира дати → системата проверява застъпванията → създава резервация.
4. Служител преглежда новите заявки → потвърждава/отхвърля → клиентът вижда актуализация.
5. Администратор обновява цена/наличност → промените се появяват в публичния каталог.

## Нефункционални изисквания

- **Сигурност:** Identity, пароли като хешове, роли, анти-CSRF защита за POST форми, параметризирани EF заявки, валидация на входа, HTTPS, secret storage.
- **Качество:** минимум 65% unit test coverage на изпълнимите редове в бизнес логиката (краен критерий, не постигнат в Етап 1).
- **Производителност:** целево зареждане на каталог до 3 сек. при тестови 500 продукта на локална среда.
- **Ползваемост:** responsive интерфейс за телефон, таблет и компютър; ясни валидационни съобщения; две персонализирани грешки.
- **Поддръжка:** отделяне на UI, бизнес логика и достъп до данни, използване на Git и документиране на промените.
- **Публикуване:** публичен URL и демо акаунти за трите роли преди крайното предаване; без реални пароли в хранилището.

## Граници на Етап 1

**Предадено като файлове:** концепция, проучване на 3 приложения, архитектурен и DB дизайн, базова MVC структура, 5 основни domain entities + Identity user, 5 контролера, 6 начални публични/защитени изгледа, GitHub Actions конфигурация и 4 начални unit теста.

**Трябва да се изпълни в местната среда:** възстановяване на NuGet, генериране и прилагане на миграция (или алтернативен SQL скрипт), локално стартиране и качване в съществуващия GitHub репозиторий.

**Следващи етапи:** завършени покупки, реални резервации, CRUD, deployment, два специални error изгледа, CI/CD с deployment, интеграционни и security тестове и документиран отчет за покритие.
